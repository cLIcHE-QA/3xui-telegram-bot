# Git workflow

Основная ветка: `main`.

Новые изменения выполняются через отдельные ветки:

- `feature/<name>` — новая функциональность;
- `fix/<name>` — исправление;
- `hotfix/<name>` — срочное production-исправление;
- `chore/<name>` — инфраструктура/документация.

Типовой цикл:

1. Создать ветку от актуального `main`.
2. Внести изменения и локально проверить Python syntax/tests.
3. Обновить `CHANGELOG.md` для релизных изменений.
4. Открыть Pull Request.
5. Проверить diff/CI и выполнить merge.
6. Для релиза создать tag `vX.Y.Z` на merge commit.

Исторические теги до `v4.8.0` восстановлены по сохранённым release snapshots при миграции проекта в Git.
