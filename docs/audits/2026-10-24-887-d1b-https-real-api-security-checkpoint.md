## Addendum: обработка HTTPException при отрицательных ответах (2026-10-24)

- После первоначального GitHub CI по test commit `f77e3140d7bc908abd07eb14f247437927158177` установлено **1417 Python tests, 3 skipped, PASS**; три новых TLS→real-backend теста участвовали в полном наборе. В Python job log явно виден `DeprecationWarning: returning HTTPException object is deprecated` из `aiohttp.web_protocol.py` на guest/foreign-origin отказах.
- Исправлена `secure_response`: защита headers сохраняется, но `HTTPException` после установки headers **повторно поднимается** через `raise`. Это future-compatibility и fail-closed denial path hardening, **не доказательство эксплуатируемой уязвимости**. Добавлен отдельный unit test на оба отрицательных ответа, CSP/no-store/nosniff/frame headers и отсутствие такого warning. Результат **нового** exact-head GitHub CI должен быть независимо прочитан после docs/code commit, PASS с предыдущего SHA не переносится.
- Весь scope остаётся offline synthetic; никакого Nginx/live D1b service/сертификата/deploy/production mutation на VPS и никакого изменения Published/Deployed нет; #887 keep_open, D2/D3 PENDING.
